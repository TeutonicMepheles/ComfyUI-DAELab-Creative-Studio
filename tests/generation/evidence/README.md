# M4 shared generation implementation handoff

Implementation and deterministic offline validation only. No stage gate or real provider/GPU acceptance is claimed. The suite uses a temporary real SQLite JobLedger, AssetCatalog, synthetic media decoded by the shared validator, injected providers and native queue stand-ins. Production imports/disabled assembly do not start models, processes, downloads or network requests.

## Public composition

`GenerationService(core.jobs, core.assets, providers={provider.id: provider}, admission=admission, poll_interval=1, poll_limit=3600)` is shared by standalone and table generation and by canvas/table optimization. `backend/providers/contracts.py` defines the injection protocol. A provider supplies `id`, `execution_kind`, `resource`, query/lookup/cancel capability flags, synchronous `build(data, frozen_media, request_id)`, and async `capabilities(model)`, `preflight(snapshot)`, `create(request_id,snapshot)`, `query(task_id,snapshot)`, `lookup(request_id,snapshot)`, `cancel(task_id,snapshot)`. Observations carry an original task ID and either completed text or rooted output file descriptors; the application commits success only after the shared result validator accepts the receipt.

Allowed model to provider mapping:

| UI model | Provider ID |
| --- | --- |
| Qwen-Image-2.1 Turbo（本地） | local-qwen-image |
| MiniMax H3 FL（本地） | local-h3 |
| qwen3.5:9b-q4_K_M or canvas alias qwen | local-qwen-text |

Explicit test providers can use those IDs, a fake Admission lease and their own capabilities response. Nonlocal injected protocol fixtures must additionally declare `protocol_only=True`; there is no production cloud transport or fallback. The tests contain deterministic fixtures; they are not imported from product code. The provider can delay create/query, raise `SubmissionRejected` for a proven preacceptance rejection, or `SubmissionUncertain(task_id=...)` when delivery may have happened. Returning malformed observations also preserves an unknown submission. Credentials are rejected before snapshot persistence.

`assemble_generation(core)` is disabled by default. For explicit local activation it requires `native_queue`, `node_types`, `resolve_model(category,name)`, `lock_path`, and model bindings by `image`/`video`, each category carrying `{name,path,sha256}`. Image categories are diffusion_models, text_encoders, mmproj and vae; video categories are diffusion_models, text_encoders, video_vae, audio_vae and loras when turbo is selected. `resolve_model` must be the host's actual name resolution (for example its existing folder_paths.get_full_path function), so hashing a shadow file cannot establish readiness. `release_native_models` and transport `ensure_unloaded` (read-only residency verification) are needed for local Qwen admission. Missing exact capabilities are unavailable, never downloaded or selected by fallback.

Actual fixed H3 evaluation uses the runtime manifest's NVFP4 diffusion model and FP16 video VAE, explicitly bound by their names and hashes; old model filename constants do not override those bindings. The ten comparisons explicitly set non-turbo H3 and fixed seeds. Native parameter defaults remain source-derived; explicit settings are preserved in the frozen job.

Use `ComfyNativeQueue(server, execution.validate_prompt, interrupt_owned=...)` from the integration module. The actual pinned 3c1b7a17 host exposes mutex-protected interrupt_if_running(prompt_id); the adapter can use it directly. For an explicit stricter owner check, `owned_native_interrupt(server.prompt_queue, comfy.model_management.interrupt_current_processing)` supplies an explicit adapter. It holds the host queue mutex while verifying exactly one running task and matching both native task ID and application request ID. It refuses foreign or multiple runners. An interrupt request is not cancellation completion: the original native history must confirm interruption. Pending cancellation deletes only the matching owned queue item. Missing host ownership capabilities fail closed.

Call `register_nodes(service)` and `register_routes(server, service)` explicitly from root assembly. The stable native node remains **DAELAB.LibTV.VideoGenerate**, with all 17 input and 5 output positions preserved. It only reads a verified current completed result. The old LibTV executor is not imported or reactivated. `install_native_admission(server, admission)` must be explicitly installed before aiohttp freezes middleware; it guards native prompt admission with the same resource lease. All processes participating in local GPU admission must share the configured lock path. Arbitrary external processes that ignore this lock cannot be claimed as controlled by this package.

## HTTP and durable boundary

There are 23 explicit routes. GET `/daelab/studio/generation/capabilities?model=...` calls the injected provider's read-only capability probe. POST generation `submit` takes `{jobs:[{requestId,input,source?}]}`. Input is a frozen structured model config/segments/assets DTO. `status` takes `{requestIds}` and only reads ledger facts. `recover` queries/looks up the original provider identity; it never invokes create. `cancel` and `pause` record intent and cancel only confirmed owned work. `retry-local` requires a failed/cancelled original and a distinct `{requestId,newRequestId}`; it preserves the original fact and seed. `reconcile-resource` is an explicit quarantine recovery action, not a model-readiness proof. `/daelab/studio/optimization/submit` uses the same generic task DTO. Reports include `version`, `inputFingerprint` and `source`; frontend writeback must use the DocumentController ticket bridge owned by the other agent, never mutate node tables directly.

The eleven original table optimization actions are POST `/daelab/prompt-optimization/{capabilities,estimate,lease,submit,query,recover,permit,advance,stop,continue,skip}`, with `contractVersion:1`. `/daelab/prompt-optimization/polish` retains the independent local Qwen DTO. Table estimate/submit freeze and validate but never execute. A short lease and one-shot permit authorize a selected row; `advance` schedules that row through the same GenerationService and shared admission. Batch membership and original snapshots reside in immutable JobLedger source/snapshot fields. Quotes, leases, permits and UI pause controls are ephemeral; a new service reconstructs batches paused. Query performs no provider create/query and no durable mutation. Recover may only query original IDs. Stop prevents an unsent worker from crossing the durable submission boundary even while it waits for a resource. An active model response remains tracked and can finish as a fact. Continuing stopped unsent rows is explicit; it cannot overlap a replacement batch. No separate JSON/SQLite ledger, generic task engine or old service executor was copied.

Root now provides `JobLedger.list_jobs(source_filter={operation,batchId,documentId,tableId},offset=0,limit=500)` with SQL filtering before pagination; the facade uses that public API only. `JobLedger.begin_submission` remains the atomic durable single-create claim. Restart reconciliation is explicitly the root lifecycle's responsibility and must occur only after old workers are stopped. Neither import nor health automatically reconciles, retries or dispatches work.

## Evidence and limits

- Both Python 3.12 (actual Comfy environment) and Python 3.14 run the suite; command and results are in the adjacent validation JSON/text reports.
- The ten public fixtures compare old pinned final request dictionaries with new constructors. Only output prefixes and rooted input locations are normalized. Independent text/reverse use 8192 context and 768 output; table uses 16384 context and its frozen output budget; temperature .4, no seed for text, think/stream false, keep_alive 0. Qwen image and H3 node parameters, structured references and frame order compare exactly.
- The table test receives the captured frozen wire prompt; it proves the new provider preserves that wire body, not that it independently reimplements frontend freezeSnapshot. Frontend document and reference freezing is tested by its separate owner.
- Root's H3 CPU preprocessing capture is separate evidence: actual LoadImage/resize/tokenizer/VAE-boundary ordering with encoder stand-ins. It does not establish real model inference or the live run's tensor hashes.
- `first-failure.txt` preserves the first test failure. The harness patched subprocess.Popen before importing Windows asyncio, breaking its subclass definition; preloading asyncio in that child fixed the harness. The production no-startup-IO assertions remained enabled.
- During development a full suite exposed a wait_idle busy loop: already-completed worker handles could starve their retirement callbacks. Explicit retirement fixed it. This observation has no separate raw capture and is not represented as a fabricated failure log.
- Hash/format/whole-media validation, missing results, traversal, changed frozen inputs, ownership, one-shot submission, restart query-only recovery, bounded recovery, exact model names/hashes/resolution, lease/revision conflicts, and known rejection versus uncertain delivery are exercised. Real browser scope switching, real provider delays/network failures, GPU release, current native cancellation and output quality still require the root-controlled acceptance runs.
- Backend routes are ready for the business HTTP adapter; this subtask did not edit frontend binding, root bootstrap or product diagnostics. No live/cloud request, charge, model load or workflow execution was used to make these tests pass.

## Qwen fixed weight and release follow-up

`assemble_generation(..., qwen_binding=binding)` explicitly accepts `QwenModelBinding` from `backend/providers/qwen_binding.py`. Construct it with `manifest_path`, the actual `installed_manifest_path` used by the configured Ollama registry, `blobs_root`, `expected_manifest_sha256`, and all six `{role,sha256,bytes}` entries (model, projector, config, template, license, params). Construction performs no reads. Build/preflight inspect the fixed registry manifest, byte-identical installed manifest, exact descriptor membership and every actual blob hash. Verified file stamps cache repeated blob hashing; changed files are rehashed. No pathname or private local root is included in the public receipt metadata.

The task's prepared snapshot stores the verified `weights` metadata. Every dispatch and provider create rechecks it. Read-only tags must report the exact model name and the manifest digest, and ps must establish empty residency before new inference. A same-name replacement, changed installed manifest/blob, missing binding, stale frozen binding or unknown/occupied residency is unavailable before generate. The supplied verification interface can be explicitly replaced only by a test-owned binding; product assembly never invents a successful binding.

Read-only inspection of the existing baseline registry and installed manifest found identical bytes with SHA256 `56671c2ab9385f9cfcb404638e32cd62d88e3501d44822208363c010179a3c90`. The expected six blob hashes are supplied by the fixed runtime baseline. This follow-up did not rehash the real multi-GB blobs or contact the running service; synthetic six-blob registries exercise changed hash/membership/digest failures. Actual activation will perform the configured real verification and remains a separate controlled step.

`LoopbackOllama.ensure_unloaded` now only polls GET ps. It never sends an empty generate/unload request because ps cannot prove another client's ownership. The service's own real request retains the original keep_alive=0 body; its normal completion asks Ollama to release that request's model. Any resident or unobservable model leaves admission quarantined. Explicit reconcile also only observes release; it does not kill or unload outside work. The deterministic host fixture never instantiates this transport or LocalAdmission.

The earlier note about a missing task-scoped host interruption method came from inspecting a different packaged Desktop copy. It was corrected against the actual host path in the fixed runtime baseline; no host source was modified.

## Scoped frontend reference follow-up

New result readers use `row.meta.studioGenerationRefs[fieldId][-1]`. For a new reference, `task_data.sourceScope` must supply stable documentId/tableId/nodeId. The reference source, frozen ledger source and selected current row/field must agree on all five identities; model and immutable media receipt must also match. Missing new scope or a foreign target rejects reading. When no new reference exists, the prior rooted historical-result read remains available and never revives old execution. Frontend inputDigest is its own input-order hash and is not misrepresented as the ledger's broader inputFingerprint.

Independent polish accepts optional `sourceScope` and freezes it as job.source. It retains the old result/model/provider/usage DTO and additionally returns the report source, inputFingerprint, receipt, version, state, taskId and phase. A reused request ID with a different scope is rejected without another create. Native current-input or late-result application remains the frontend DocumentController owner's responsibility.


The preflight race fix adds POST `/daelab/studio/generation/fence-unsubmitted` and `/daelab/prompt-optimization/fence`. A missing row is never proof of no submission. An explicit original-ID fence competes in the same SQLite JobLedger with late prepare; only a cancelled, cancellation-requested, zero-attempt fact permits a replacement. Normal claimed execution wins unchanged. A prompt-free barrier is non-executable even if interruption occurs before its terminal cancellation. Automatic definite preparation refusal may record the same safe barrier only with validated complete correlation scope. The optimization fence accepts either the validated original intent or a bounded prompt-free `{batchId,quoteId,range,references:[{requestId,source,revision,requestSeq}]}` projection; caller scope/digest/revision must match any existing fact. No barrier stores unvalidated model input or credentials.

Reproduction and first-failure logs remain under ignored `.local/validation/`; public tests use generated data only. Source-only checks do not establish actual ComfyUI/provider acceptance. The prior host snapshots predate this fix.
