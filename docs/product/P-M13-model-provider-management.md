# P-M13 模型与提供方管理

2026-11-02。本文件定义模型与提供方管理的产品行为。当前实现采用显式本地模型配置，
本文件中的自动发现和统一可用性状态是目标行为，不代表已经实现或完成宿主验收。

## 范围

首版覆盖：

- ComfyUI 本地图片模型。
- ComfyUI 本地视频模型，包括 FL 与 Ref。
- 本地 Qwen / Ollama LLM。
- DeepSeek API，当前支持 `deepseek-flash`。

后续提供方沿用相同目录、状态和消费合同。模型与提供方管理不执行推理，不拥有任务账本，
也不改变各任务资源准入规则。

## 用户目标

- 服务启动、应用打开或宿主重连后，自动建立当前机器可用的模型目录。
- 用户在生成节点和 LLM 优化节点中看到一致、可解释的模型可用状态。
- 配置变化或页面刷新后，无需逐节点重新读取即可恢复当前可用模型。
- 已保存工作流继续引用稳定逻辑模型；机器路径或服务状态变化不能静默改成另一模型。

## 核心对象

| 对象 | 定义 |
| --- | --- |
| 提供方 | 执行模型运行或 API 调用的边界，例如 ComfyUI 本地、Ollama、DeepSeek。 |
| 逻辑模型 | 工作流和业务配置引用的稳定产品模型身份。 |
| 运行时绑定 | 当前宿主上的节点、文件、清单、端点和提供方配置。 |
| 能力快照 | 当前逻辑模型支持的类型、模式、参数、素材约束及可用状态。 |
| 可用性状态 | 面向用户的检测结果及不可用原因。 |

工作流保存逻辑模型身份和用户选择。物理路径、文件哈希、Ollama 清单、DeepSeek 凭据及
端点属于机器配置或运行时状态，不写入工作流业务数据。

## 自动发现与刷新

宿主就绪后执行一次低成本发现，不加载 GPU 模型，不发送计费请求。以下事件使相关快照
失效并重新检测：

- ComfyUI 服务启动或重连。
- 页面刷新或应用重新打开。
- 本地模型配置发生变化。
- DeepSeek 凭据新增、移除或切换作用域。
- 用户选择“重新检测”。
- 提交任务前再次确认所选模型和提供方仍满足能力要求。

检测结果由 `P-M13` 统一发布。`P-M08` 提示词与 LLM、`P-M10` 图片与视频生成及多维表格
消费同一结果，不各自探测模型。

## 提供方检查

| 提供方 | 基础检查 |
| --- | --- |
| ComfyUI 本地图片/视频 | 所需节点、模型类别、文件是否存在、宿主解析路径、文件哈希及声明的生成模式。 |
| 本地 Qwen / Ollama | 回环服务是否可达、已安装模型列表、注册清单、六个 blob、模型名称和 digest。 |
| DeepSeek API | 官方端点适配是否可用、支持模型身份，以及 `DEEPSEEK_API_KEY` 是否来自宿主环境、用户配置或当前页面会话。 |

DeepSeek 检测不得自动提交一次优化请求，也不得以会产生计费的方式验证凭据。能够安全读取
非计费认证或模型信息时，可验证后标为“可用”；否则只标记“待验证”。

本地检测不自动启动 Ollama、不下载模型、不用其他权重或量化版本替换缺失模型。Ollama
未运行是可见不可用状态，不是自动启动请求。

## 模型列表状态呈现

生成节点、LLM 优化节点和多维表格的模型选项列表采用隐式状态提示，不显示常驻文字
Tag。模型名称和提供方来源仍单独显示。

| 状态 | 视觉与交互 |
| --- | --- |
| `可用` | 保持普通模型选项样式，可以选择并进入参数配置；提交前仍执行最终校验。 |
| `检测中` | 模型选项名称后显示加载圆环；检测结束前不得提交任务。 |
| `待验证` | 保持普通、可选择的选项样式；选中后显示“首次提交时验证”的简短说明，不显示常驻 Tag。首次提交验证失败时阻止提交并更新为不可用。 |
| `不可用` | 整个模型选项置灰并禁用，不能选择或提交；通过可访问说明或邻近提示给出原因。 |

加载圆环必须提供“正在检测此模型”的可访问名称。不可用状态除置灰外，还应通过禁用
语义、不可用光标或辅助说明表达，不能只依赖颜色。原因内容包括“未安装模型”“缺少
节点”“Ollama 未运行”“需要配置 DeepSeek 密钥”“凭据无效”或“模型身份冲突”等。

列表行为：

- 可用模型保持默认外观，不额外显示勾选标签或“可用”文字。
- 当前模型从可选变为不可用时，保留其逻辑身份和可见选择，将其控件置灰禁用并显示原因。
- 不静默选择其他可用模型，不改变工作流中的模型 ID。
- 检测完成后原位更新模型行，不重复生成列表项。
- 状态变化不能关闭用户正在编辑的配置，也不能清除未提交草稿。
- 模型选项较多时，加载圆环和原因不能导致菜单横向溢出；键盘、焦点和读屏名称保持可用。

选中的模型控件在不可用时同步置灰禁用；检测中时同步显示加载圆环。待验证状态不增加
常驻视觉标记。

## 匹配与冲突

- 自动匹配只接受产品支持且能力完整匹配的逻辑模型。
- 同一逻辑模型存在多个候选时，优先使用用户明确保存的提供方和绑定；仍不唯一时标记为
  “模型身份冲突”，不猜测。
- 当前工作流引用的模型不可用时，保留原配置并报告原因，不自动回退到云端、其他量化
  版本或相邻模型。
- 用户显式切换模型时，只迁移新模型声明支持的设置；无效隐藏参数不继续提交。

## 数据与安全

- DeepSeek 密钥不得进入工作流、任务快照、账本、诊断导出或可用性说明。
- 诊断只报告凭据来源和状态，不显示密钥值。
- 本地模型路径、清单和哈希属于机器运行配置，不提交源码或公共夹具。
- 能力快照是只读投影；编辑数据仍由原生工作流拥有，任务事实仍由 SQLite 账本拥有。

## 消费模块

| 模块 | 消费方式 |
| --- | --- |
| `P-M08` 提示词与 LLM | 获取 Qwen、DeepSeek 等 LLM 模型、优化能力和可用性状态。 |
| `P-M10` 图片与视频生成 | 获取图片/视频模型、模式、参数 schema、模式和可用性状态。 |
| `P-M11` 任务与资源管理 | 在执行时补充 GPU、模型驻留和提供方容量状态，不改变模型身份。 |

## 当前实现与差距

当前本地模型通过 `daelab/creative-studio/local-generation.json` 显式装配，检查 ComfyUI
节点、模型路径、哈希、Ollama 清单和 blob；DeepSeek 支持宿主环境、用户配置及当前页面
会话中的密钥。现有控件能够显示部分不可用文字，但尚无统一的跨节点模型目录和本标准
定义的隐式可用性呈现。

权威实现边界见[本地模型装配](../architecture/LOCAL_GENERATION.md)、
[模型配置](../MODELS.md)和[提供方合同](../../backend/providers/README.md)。

## 待验收场景

1. 应用启动后，本地图片和视频模型显示真实可用性及原因。
2. Qwen 可用、Ollama 停止、清单不匹配时分别显示正确状态。
3. DeepSeek 密钥缺失、存在但未验证、验证成功和失效时显示正确状态。
4. 服务重启和页面刷新后重建目录，生成节点与 LLM 优化节点显示一致状态。
5. 当前选择失效时保留模型身份，不自动切换，并阻止提交。
6. 不可用项不能只依赖置灰表达，键盘和读屏可取得禁用状态与原因。
7. 检测中的圆环具有可访问名称，完成后原位替换为可选择或置灰禁用状态。
8. 开放模型列表不会因圆环或原因产生横向溢出。

上述场景尚未形成 F/AC/UC/TC 追踪记录；后续实施前需将其关联到现有能力目录并分配测试。
