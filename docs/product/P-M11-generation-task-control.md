# P-M11 生成任务控制

2026-11-02。本文件定义图片、视频、文本生成及 LLM 优化任务的产品控制行为。当前实现
已有部分取消、暂停和本地重跑能力；本文件中的完整范围、统一语义和持久暂停状态是目标
行为，尚未实现或完成宿主验收。

单个任务的数值进度及批量完成比例另见
[单任务进度产品说明](P-M11-generation-task-progress.md)。

## 用户目标

- 对任何已创建的生成任务，都能明确执行等待、暂停、打断、继续或重启。
- 单个任务的停止不误伤其他行、其他节点或其他表格实例。
- 页面刷新、工作流重开或服务重启后，任务状态和暂停意图仍有真实依据。
- 使用户能够停止当前工作，同时避免重复提交、重复计费和覆盖旧结果。

## 控制范围

控制动作适用于：

- 单个生成任务。
- 当前所选任务。
- 当前节点或当前生成列的任务集合。
- 已提交批次中的剩余任务。

每个动作必须带有明确范围。界面不得用“暂停任务”却实际作用于整个工作流，也不得用
“停止当前”却取消未被选中的其他实例。

## 动作语义

| 动作 | 用户意图 | 任务事实 |
| --- | --- | --- |
| 暂停 | 暂时停止继续工作，稍后希望恢复 | 停止派发后续任务；当前执行在确认停止后进入可恢复的暂停状态 |
| 打断 | 立即结束当前执行，不计划自动恢复 | 当前任务进入已打断或待确认中断状态，旧尝试保留 |
| 继续 | 恢复暂停的任务集合 | 未提交项继续原身份；已开始但被停止的执行创建新尝试 |
| 重启 | 从头重新执行一个已结束任务 | 创建新请求身份，旧任务、旧回执和旧结果保持不变 |

“暂停”与“打断”可以调用相同的底层中断能力，但产品含义不同：暂停保留继续意图，
打断结束当前任务。界面、状态和持久记录必须能够区分两者。

## 状态与动作矩阵

| 当前状态 | 暂停 | 打断 | 继续 | 重启 |
| --- | --- | --- | --- | --- |
| 等待派发 | 保留任务并暂停派发 | 标记为已打断 | 恢复原等待任务 | 不建议使用；应先取消原等待任务 |
| 本地运行中 | 请求作用域内中断，确认后暂停 | 请求作用域内中断，确认后打断 | 暂停后从冻结输入创建新尝试 | 等待原执行结束 |
| 可取消远端运行中 | 请求提供方取消并等待确认 | 请求提供方取消并等待确认 | 仅恢复未提交部分；已开始项按新尝试处理 | 等待原执行结束 |
| 不可取消远端运行中 | 停止后续派发，当前请求继续 | 记录打断意图并继续查询原执行 | 当前完成后继续剩余任务 | 等待原执行结束 |
| 结果未知或待恢复 | 停止派发新工作 | 记录打断意图，不自动重提 | 先查询原任务 | 原任务核对前禁用 |
| 已完成 | 不适用 | 不适用 | 不适用 | 按原冻结输入或当前编辑输入重新生成 |
| 失败、已打断或已取消 | 不适用 | 不适用 | 不适用 | 使用新请求身份重启 |

动作进入“暂停中”“打断中”或“重启中”后，必须等待后端证据推进状态，不能先显示为
完成。重复点击使用同一意图，不创建重复控制请求。

## 暂停与继续

- 暂停首先停止派发新的任务，不影响其他实例。
- 对正在执行的本地或可由 Studio 精确拥有的任务，发起作用域内中断；确认停止后才显示
  “已暂停”。
- 无法暂停的 GPU 推理不保存中间张量或生成进度。继续已中断的当前项时，从冻结输入
  创建新的执行尝试和请求身份，并关联旧请求；未提交的等待项保留原任务身份。
- 远端任务只在提供方明确支持取消时请求取消。取消未确认时显示“暂停请求中”或继续查询，
  不宣称远端执行已经停止。
- 暂停意图必须持久化。页面刷新、工作流重开和服务重启后，任务不会自动继续，必须由用户
  显式选择“继续”或“重启”。
- 当前任务在暂停请求生效前已经完成时，保留完成结果，不重新执行该项。
- “继续”继续剩余等待任务前，必须重新核对当前输入、模型可用性和费用确认条件。

## 打断

- 打断可作用于单个任务或明确选中的任务集合。
- 等待任务不再派发，直接保存为已打断。
- 本地或 Studio 拥有的原生任务使用请求 ID 和提供方任务 ID 双重匹配后中断；发送中断
  不等于确认停止，只有宿主或提供方返回对应终止证据后才进入已打断。
- 可取消远端任务发出提供方取消请求；未确认前保留原任务状态并继续查询。
- 对无法取消的远端请求，界面只能表达“已请求打断、执行仍可能继续”；不得显示已停止、
  已退款或已释放付费事实。
- 打断不会自动提交替代任务。用户需要后续重启时必须显式操作。
- 打断任务所在节点被隐藏、停用或销毁不会改变任务事实；重新打开后从账本恢复状态。

## 重启

- 重启始终创建新的 `requestId`，旧任务的事件、尝试、回执和结果只读保留。
- 用户可选择“按原冻结输入重启”或“按当前编辑输入重启”：
  - 原冻结输入用于忠实重跑，要求原始素材引用仍可验证。
  - 当前编辑输入必须重新预检、冻结和确认费用。
- 重启不是恢复。不得复用原请求 ID、覆盖原提供方任务 ID，或把旧成功结果当成本次结果。
- 已完成任务、失败任务、已打断任务和已确认取消任务可以重启。
- 运行中任务不能并行重启。结果未知或待恢复任务必须先核对原执行，避免重复计费或产生
  两个互相竞争的结果。
- 批量重启为每个目标分配独立请求身份；某个目标失败不回滚其他目标。
- 重启不会删除旧结果；新结果按稳定行、列、字段和目标身份写入。

## 界面行为

- 任务状态区提供与当前状态相容的动作；不可用动作可以隐藏或禁用，但图标、名称和作用
  范围必须可区分。
- 暂停、打断和重启使用不同图标和可访问名称，不能统称为“取消”。
- 对正在运行或可能产生费用的任务执行打断前，需要一次明确确认。
- 操作后立即显示“暂停中”“打断中”或“重启中”，并提供真实任务身份或范围摘要。
- 暂停与继续作用于明确范围；生成列、节点和选区工具栏显示当前影响范围。
- 一个动作正在处理中时，重复点击不能产生第二个控制请求。
- 任务胶囊保持只读；控制入口位于任务所属面板，避免关闭胶囊、隐藏节点或撤销编辑造成
  隐式取消。
- 任务状态、暂停意图和进行中控制不得写入工作流、节点属性或撤销历史。
- 动画、旋转状态和错误展示遵循全局减少动态效果与可访问性规则。

## 提供方边界

| 提供方状态 | 产品行为 |
| --- | --- |
| Studio 本地队列等待项 | 可直接暂停、打断或取消派发。 |
| Studio 拥有的 ComfyUI 原生执行 | 按应用请求 ID 和原生任务 ID 双重匹配后请求中断，等待原生终止证据。 |
| 支持查询和取消的远端执行 | 请求原提供方取消；最终状态以提供方查询为准。 |
| 仅能查询、不能取消的远端执行 | 停止后续工作，继续跟踪当前请求，不显示已停止。 |
| 不能查询或取消的远端请求 | 保留提交结果未知状态；不自动重提，不释放未决资源。 |

DeepSeek、Qwen 或其他提供方是否支持查询与取消，由 `P-M13` 发布的提供方能力合同决定。
产品不能因为存在“打断”按钮就推断远端请求可以撤销、停止计费或恢复为未提交状态。

## 持久化与并发

- 任务状态、事件、尝试、提供方任务 ID 和终态继续保存在统一 SQLite 账本。
- 暂停范围和暂停意图必须跨页面及服务重启保持，不能只存在于窗口或节点面板。
- 继续和重启使用版本校验，防止旧页面覆盖其他实例的新状态。
- 同一请求的暂停、打断和完成回执竞争时，已提交终态优先；用户意图和实际结果都保留。
- 最终清理必须等提供方进入可确认终态，未知远端执行继续保留资源占用。
- 多个任务并发时，请求 ID 是控制边界；不能使用“当前运行项”猜测用户目标。

## 当前实现与差距

当前统一账本已区分取消意图与确认取消，本地原生执行支持作用域内中断，已确认停止或失败
的本地任务可显式以新请求重跑；任务胶囊只读，控制入口位于生成及优化面板。

当前产品入口仍把主要控制暴露为“暂停”，其底层通过取消接口实现；远端已提交任务通常
继续完成。完整的任务级暂停/继续、持久批次暂停、统一打断状态、所有提供方的显式重启
以及跨刷新恢复仍属于本文件定义的目标需求。

## 待验收场景

1. 等待中的单个任务暂停后不派发，继续时保持原请求。
2. 本地运行任务打断后只有宿主终止证据到达才显示已打断。
3. 本地当前项暂停后继续，创建新尝试且旧尝试记录仍可查看。
4. 可取消远端任务等待确认，不提前显示已停止或已退款。
5. 不可取消远端任务停止后续派发，当前请求继续跟踪。
6. 已完成、失败、已打断和已取消任务均可重启，并生成新请求 ID。
7. 运行中和结果未知任务不能绕过原任务核对直接重启。
8. 暂停、打断、继续和重启只影响明确范围；其他实例继续运行。
9. 刷新、工作流重开和服务重启后暂停任务不自动继续。
10. Undo/Redo、隐藏任务胶囊和销毁节点不会取消或重启真实任务。

上述场景尚未形成新的 F/AC/UC/TC 追踪记录。现有相关能力为 F-BIZ-030 至 F-BIZ-035、
F-SYS-007/010/019，以及 UC-BIZ-011/012、UC-SYS-004/008。
