# P-M11 单任务进度

2026-11-02。本文件定义生成节点处理单个或一组任务时的进度呈现。当前任务视图和输出占位
已有可选百分比入口，但后端提供方尚未稳定提供完整的单任务数值进度；本文件是目标产品
需求，不代表对应数值已经可用或完成验收。

## 用户目标

- 在生成节点和自动输出占位中看到每个任务自己的状态与百分比。
- 能区分“当前任务执行到 35%”和“整批任务已完成 3/10”。
- 只在存在真实进度来源时显示百分比，不接受按时间推算的假进度。
- 刷新、暂停、打断和重启后，百分比不会倒退、冒充旧尝试或错误推进。

## 进度类型

| 类型 | 定义 | 呈现 |
| --- | --- | --- |
| 单任务进度 | 某个 `requestId` 当前执行尝试的数值进度 | 显示明确百分比，例如“生成中 35%” |
| 阶段进度 | 已知执行阶段，但没有可核对的数值 | 显示“排队中”“准备中”“提交中”“生成中”“下载中”等 |
| 批量完成比例 | 已完成任务数与任务总数的比例 | 显示“已完成 3/10”，不能替代单任务百分比 |

单任务百分比按任务身份隔离。并行任务、多个节点或多个表格实例各自拥有独立进度，不能
把其中一个正在运行任务的百分比复制给其他任务。

## 数值来源

- 百分比只能来自提供方、宿主队列或可核对的执行计数。
- 允许由提供方报告已完成单位与总单位换算百分比；换算关系必须稳定且有对应任务身份。
- 禁止使用固定时间、动画、随机值或未经校准的阶段权重生成百分比。
- `P-M13` 发布提供方是否支持单任务数值进度；`P-M11` 维护任务进度状态；`P-M10` 只消费
  并呈现结果。
- 后端观察、任务投影和前端显示必须使用同一 `requestId`、执行尝试和阶段，迟到响应不能
  覆盖新的尝试。

## 显示规则

### 单个任务

- 生成节点只有一个活动任务时，可在自动输出占位内显示阶段和数字百分比。
- 百分比必须同时显示数字和 `%`，不能只靠圆环填充程度表达。
- 有真实数值时使用确定进度条或环形进度，并提供 `aria-valuemin`、`aria-valuemax`、
  `aria-valuenow` 和可读文本。
- 没有真实数值时显示不确定进度圆环或阶段文字，不显示虚构百分比。
- 排队状态不显示 `0%`，应显示“排队中”。只有执行已经开始且提供方明确报告零进度时
  才可显示 `0%`。
- 生成阶段达到 `100%` 不等于任务已经成功。若仍在写回或校验，显示“生成 100% · 等待
  写回”或对应阶段；只有结果完成验证后才显示任务完成。

### 一组任务

- 每个任务对应的输出占位分别显示自己的阶段和百分比。
- 节点级或生成列级胶囊显示批量完成计数和整体状态，不把当前单个任务的百分比当作整批
  百分比。
- 多个任务并行时，胶囊显示真实完成数；每个活动任务在自己的占位中显示各自百分比。
- 任务组排序、名称和占位身份保持稳定，更新进度不得重建占位或打乱顺序。
- 没有可用结果的行也保留占位和进度状态，不能因尚未完成而从任务组消失。

### LLM 优化

- 若提供方报告真实 token 或行级进度，可在对应行显示百分比。
- 没有可核对数值时显示“等待模型响应”和已完成行数，不推算百分比。
- 优化批次的百分比不得与图片或视频生成占总任务比例混合。

## 状态变化

| 状态 | 进度呈现 |
| --- | --- |
| 等待派发 | 不显示数值，显示“排队中” |
| 准备、提交、生成、下载 | 仅在当前阶段有真实来源时显示百分比，并同时显示阶段 |
| 暂停中或打断中 | 保留最后一次已确认状态，不继续动画或推进数值 |
| 已暂停或已打断 | 以任务状态为主；百分比不再变化，可保留为历史详情 |
| 结果未知或待恢复 | 不推进百分比；显示最后确认时间和需核对原任务的状态 |
| 重启或新尝试 | 新任务从无进度或真实零进度开始，不继承旧尝试百分比 |
| 已完成 | 显示完成状态；是否显示 100% 取决于百分比是否覆盖到已验证完成 |

## 数据与更新规则

- 同一执行尝试内，单任务百分比应非递减；非法、负数、超过 100 或跨任务身份的更新拒绝
  或忽略，并记录日志。
- 内部可保留小数，界面按整数百分比显示，避免制造虚假精度。
- 更新频率按视图动画帧或现有任务同步节奏合并，不对每个底层进度事件立即重排界面。
- 百分比、阶段和更新时间应作为同一快照提交，不能由不同轮询结果拼接。
- 通过页面刷新或工作流重开恢复时，先显示后端可确认的最近状态；没有依据时显示“核对
  任务状态”，不沿用前端缓存中的假运行状态。
- 进度是运行时任务事实，不写入工作流、节点属性、撤销历史或资产收藏数据。

## 可访问性与布局

- 数字百分比使用等宽数字，更新时不得导致卡片宽度抖动。
- 确定进度通过进度条或环形进度表达，同时保留数字；不确定进度不设置虚假的
  `aria-valuenow`。
- 减少动态效果时禁用旋转和过渡，但仍显示数字或阶段文字。
- 占位空间不足时优先保留状态与百分比，再次压缩时可只保留圆环和百分比；详细阶段进入
  悬停或可访问说明。
- 进度更新不能移动节点、改变连线锚点、抢占焦点或关闭用户正在查看的预览。

## 提供方能力

| 提供方或执行环境 | 产品呈现 |
| --- | --- |
| 可提供任务级完成单位的本地执行 | 显示任务阶段和真实百分比。 |
| 仅提供排队与运行状态的本地执行 | 显示不确定进度和阶段。 |
| 提供数值进度的远端 API | 按原任务身份显示百分比。 |
| 仅提供状态的远端 API | 显示阶段与等待时间，不推算。 |
| 文本 LLM 等无中间进度来源的任务 | 显示等待状态、已完成行数或流式文本状态。 |

进度能力由 `P-M13` 声明，不能因模型名称相同而假定所有提供方支持百分比。

## 当前实现与差距

当前任务快照协议允许可选的真实 `progress` 字段，生成输出占位可在收到数值时显示百分比，
节点任务胶囊在仅有一个活动生成任务时也可使用该值。当前后端提供方观察和账本公开投影
尚未稳定产生单个任务的数值进度，现有进度测试主要使用合成报告。

因此，单任务百分比 UI 入口已经存在，但真实来源、任务作用域、播放/下载阶段换算、跨刷新
恢复和所有提供方的进度能力仍未完成端到端实现与验收。

## 待验收场景

1. 单任务收到真实进度后，占位显示阶段和对应整数百分比。
2. 没有数值来源的任务只显示不确定进度，不出现推算百分比。
3. 批量任务中每个占位显示各自进度，节点胶囊保持真实完成数。
4. 多任务并行时，一个任务的进度不会显示到另一任务或整批百分比。
5. 排队状态不显示 `0%`；生成到 100% 但未写回时不能显示任务完成。
6. 暂停、打断和恢复查询期间，百分比停止推进且不冒充新尝试。
7. 重启任务后进度清零，旧任务百分比仍只属于旧尝试。
8. 乱序、重复、跨请求和非法百分比更新不会回退或污染当前任务。
9. 刷新和工作流重开后只显示有依据的最近进度或待核对状态。
10. 确定与不确定进度均可被键盘和读屏识别，减少动态效果时仍能理解状态。

上述场景尚未形成新的 F/AC/UC/TC 追踪记录。现有相关能力为 F-CAN-026、
F-BIZ-030/031/034、F-SYS-007/011/019，以及 UC-CAN-009、UC-BIZ-011/013、
UC-SYS-004/009。
