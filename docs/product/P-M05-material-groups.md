# P-M05 素材组

2026-11-02。本文件定义素材组的产品行为。当前实现仍包含跨类型素材组，本文件规定的
同类型约束是目标行为，不代表已经实现或完成宿主验收。

## 用户目标

- 把多个同类素材组织为一个有顺序、有视觉身份并可整体复用的集合。
- 在填充、输出、生成和剪辑等下游流程中保持成员顺序与素材身份。

## 素材类型

首版按以下三类判断素材是否兼容：

| 类型 | 成员 |
| --- | --- |
| 文本 | 独立文本素材及文本单元格内容。 |
| 图片 | 静态图片素材。 |
| 视频 | 视频素材。 |

素材组只包含同一类型的成员。图片和视频属于不同类型，不能仅因二者都是媒体而组成同一
素材组。

## 打组与编辑

- 当前选择全部为同类型素材时，允许打组。
- 当前选择包含两个或以上类型时，打组不可用，不能创建一个混合类型的新素材组。
- 已有素材组只接收与其类型相同的成员。跨类型成员拖入或加入该组时，不能改变组成员。
- 同类型素材允许移入、移出和排序；移除或加入成员后，组仍保持同类型约束。
- 不支持嵌套素材组。素材组不能作为另一个素材组的成员。

## 输出

- 素材组输出为有成员顺序的整组快照，保留素材类型、素材身份和成员顺序。
- 下游通过 `P-M06` 的公开连接和快照合同消费组输出，不读取私有 DOM 或依赖界面加载顺序。
- 组内成员变化只影响之后产生的新快照；已提交给下游的一次性快照不自动回写。

## 当前实现与差距

现有实现允许图片与非空文字混合成组，并以 `image-instructions` 表达图片反推要求；
[素材组合同](../material-groups.md)和现有测试保留这一行为。新目标要求新组的全部成员
同类型，因此现有实现尚未满足本文件。

旧工作流中已经保存的混合类型素材组如何处理仍需产品决策。兼容要求禁止静默删除未知或
已有数据，因此在明确迁移规则前，不应自动拆分或丢弃这些组。

## 待验收场景

1. 多选图片后可以打组；多选视频或文本也分别可以打组。
2. 同时选择文本、图片或视频中的不同类别时，打组不可用。
3. 图片组拒绝拖入视频或文本，视频组拒绝拖入图片或文本，文本组拒绝拖入媒体。
4. 同组成员排序、移入和移出后，整组快照顺序和素材身份保持稳定。
5. 保存、重载和原生撤销重做后，同类型约束与成员顺序保持不变。
6. 旧工作流中的混合类型素材组按最终兼容策略可见处理，不被静默删除或改写。

上述场景尚未建立新的 F/AC/UC/TC 追踪记录。现有 F-CAN-015 和 UC-CAN-003 包含混合组
行为，实施前需要更新关联规格或明确其替代关系。
