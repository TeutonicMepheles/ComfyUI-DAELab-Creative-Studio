# 文档写作规范

适用于本仓库全部第一方文档，包括 README、AGENTS、指南、合同、计划和验证记录。采用客观、理性、平实、简洁的文风。现有文档按模块逐步整理，不因格式统一改写历史事实或第三方原文。

## 表述

- 开头说明用途、结论或当前状态。使用具体对象和动作，保留读者完成任务所需的信息。
- 区分当前实现、拟议方案、已执行验证和未验证事项。结论注明适用范围；涉及测试时给出环境或证据入口。
- 避免宣传用语、空泛评价、反问、口号和不必要的对比句。没有证据时，不使用“完全解耦”“全面通过”“开箱即用”等结论。
- 段落保持单一主题。并列信息用列表，需要对照时用表格；简单内容不强行分节。
- 同一事实只有一个维护位置，其他文档链接引用。命令注明执行目录、前置条件及实际作用。
- 中文正文保留代码标识原文。路径尽量使用相对链接，便于在仓库中跳转。

| 避免 | 建议 |
| --- | --- |
| 打造强大而灵活的模块化架构 | 表格通过注入接口访问素材和生成服务 |
| 模块已经完全独立 | 表格核心测试无需 ComfyUI；宿主保存恢复尚待验证 |
| 全面提升用户体验 | 修复窄视口下菜单遮挡输入框的问题 |
| 测试全部通过 | 写明执行的套件、结果和未覆盖范围，并链接证据 |

## README 分工

- 根 README：产品用途、当前状态、安装、首次使用、功能与开发导航。
- 一级目录 README：职责、子模块导航、依赖方向和常用验证入口。
- 功能 README：公共入口、输入输出、依赖能力、数据归属、独立开发方式和定向验证。
- 工具与测试 README：用途、环境、命令、输入输出、副作用和证据边界。
- 资源目录 README：来源、用途、更新方式和许可。无须套用完整功能模板。
- AGENTS：操作约束与协作要求，链接 README 和权威合同，不复制功能介绍。

功能 README 的建议顺序为：职责 → 公共入口 → 依赖与数据 → 独立开发 → 验证 → 相关文档。仅记录已存在的入口；拟议命令保留在计划中。

## 修改检查

核对链接、路径、命令和功能描述。不要把计划或模拟结果写成已实现、已验收。生成文档从拥有源更新；第三方原文保留；历史失败保留日期和上下文，以新增状态说明后续变化。
