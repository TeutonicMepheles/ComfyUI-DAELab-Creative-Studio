# 迁移测试策略与阶段门禁

本策略定义迁移后的测试，不将现有旧库测试通过等同于新库通过。TC 记录是待实现、待执行的测试规格；`existing_coverage` 仅表示可复用的旧测试来源。

真实生成测试的模型白名单为本地 Qwen 与本地 MiniMax（现有视频路径为 MiniMax H3）。提示词优化中的真实模型调用也遵守此限制。其他模型和云端通道只做无真实模型调用的协议模拟；不安排付费测试，不允许云端回退。本轮文档修订不运行模型。

## 测试环境

| 环境 | 目的 | 配置与限制 |
| --- | --- | --- |
| E0 纯模块 | 领域规则、schema、导入边界、状态机 | Node 与 Python 测试进程，无 ComfyUI、网络、密钥和模型 |
| E1 后端集成 | 账本、资产、提供方协议、故障恢复 | 临时用户目录、SQLite、可编程假提供方；外网提交默认拒绝 |
| E2 最小宿主 | 注册、画布、表格、编辑、保存、媒体 | 隔离 CPU ComfyUI，只加载新包，独立 user/input/output/temp，使用测试数据 |
| E3 可选集成 | ComfyTV、声明支持的宿主及外部节点 | 与 E2 相同测试基线，记录插件版本；验证缺失时降级，不能修改上游 |
| E4 本地真实生成 | 仅本地 Qwen、本地 MiniMax | 记录本地权重、节点及 GPU；隔离资源与输出；阻断云端提交，普通 CI 不调用真实模型 |
| E5 迁移与回滚 | 旧数据读取、新旧安装切换、失败恢复 | 固定旧版本的隔离副本和新包；新旧实现不同时启用；不操作用户正在编辑的服务 |
| E6 性能与长时运行 | 画布、大表格、媒体、队列、资源释放 | 固定参考机、浏览器/宿主版本及屏幕参数；保存 trace 和采样原始数据 |

版本矩阵至少包含产品声明的最低支持宿主、默认验收宿主和发布时最新兼容候选。最低/默认版本失败阻止发布；候选失败时不得将该候选写为已支持。首版 Windows 是必测环境；若发布声明支持其他操作系统，必须补对应安装、文件路径、媒体工具和宿主验证。

每份报告记录 ComfyUI 后端与前端版本、Python/Node、操作系统、CPU/RAM/GPU、浏览器、包提交/构建指纹及可选插件。操作系统 shell 的 Python 版本不等于 ComfyUI 运行解释器版本。

## 固定夹具

以下为必须建立的夹具规格，当前文档不包含真实用户素材或生产任务数据。各 TC 的自定义 fixture 名称也应登记在未来 `tests/fixtures/manifest.json`，包括生成方式、哈希、尺寸和使用目的。

| 编号 | 内容 | 必须覆盖的变体 |
| --- | --- | --- |
| FX-MEDIA | 自生成图片、文字与短视频 | 横/竖/方图、透明图、长中文名、空文件、损坏文件、不支持格式；视频含有声/无声、非整秒时长 |
| FX-GRAPH | 原生与创作画布工作流 | 两实例、混合组、多输入、分支输出、未知节点、未知字段、旧槽位、重复文件不同节点 |
| FX-TABLE | 固定 recordId/fieldId 的表格 | 空表、普通列/素材列/提示词列/生成列、隐藏/重排列、长文本、多素材、重复行名 |
| FX-DOCX | 自建分镜文档 | 合并格、图片锚点、缺列、空行、修订内容、图片未归属、提示词列误判、重复导入 |
| FX-JOBS | 脱敏旧回执与新账本 | queued/running/success/failed/needs_recovery/unknown，远端 ID 有/无、结果文件有/无 |
| FX-PROVIDER | 可编程假服务 | 延迟、拒绝、超时、429、500、响应丢失、成功后下载失败、无取消/查询能力、重复事件、乱序事件 |
| FX-LIBRARY | 浏览器旧收藏导出 | 图片/视频/文本、重复收藏、失效引用、旧版本 schema；不同 origin 的隔离数据 |
| FX-EDIT | 确定性时间轴 | 相同文件两个节点、多组、裁剪/分割/重排/删除、静音、fit、分辨率锁、输出失效 |
| FX-PERF-S | 小型创作场景 | 100 节点、100 连线、100×10 表格、最多 2 个可见短视频预览 |
| FX-PERF-M | 日常上限场景 | 300 节点、400 连线、2 张各 500×10 的表格（合计 1000 行）、最多 4 个可见视频预览 |
| FX-PERF-L | 压力场景 | 1000 节点、1500 连线、10 张各 500×10 的表格（合计 5000 行）；验证分级呈现与取消，不要求全部媒体同时解码 |

性能夹具保持当前每表 500 行、64 列的容量合同，不以压力测试暗中新增单表扩容范围。M2 可运行纯画布/资产子场景；M3 后加入表格，M5 验收完整夹具。2000 条收藏搜索作为独立资产库负载，不等于同时创建 2000 个画布节点。

旧工作流夹具应从固定基线的真实结构制作并脱敏，保留原始 JSON 和预期解析结果。测试素材是合成内容，不能让验收依赖维护者未跟踪的本地文件。生成假服务记录每次 create/query/cancel/download 次数，使“不重复提交”可以断言。

## 测试层级

| 层级 | 主要断言 | 自动化目标 |
| --- | --- | --- |
| domain | 类型、排序、填充、引用、版本和编辑命令 | 纯 Node/Python 测试；不镜像实现细节 |
| contract | adapter、provider、schema、依赖边界 | 消费方与实现共同使用的契约夹具 |
| backend | 幂等、原子性、持久化、重启、并发和路径校验 | 临时目录/进程、故障注入与请求计数 |
| integration | 产品组装、跨模块用例、依赖和版本一致性 | 受控服务与构建产物联测，不代替真实宿主 |
| host | 实际 ComfyUI 的操作和实例生命周期 | 浏览器自动化加截图审阅；重要键盘/IME/播放行为人工补充 |
| migration | 旧数据、安装切换、版本转换和回滚 | 原始/迁移后对照、重复执行、中途失败与恢复 |
| performance | 延迟、帧时间、资源与容量 | 固定夹具、轨迹脚本和原始测量数据 |
| provider-live | 本地 Qwen/MiniMax 的输入模式与真实输出 | 仅使用白名单本地执行路径；记录设备、权重和结果，不自动替换模型 |

每个纳入功能至少关联一个 UC 和一个 TC；不迁入/暂缓项由清洁安装、缺失依赖和退役通道测试覆盖。用例和测试可覆盖多个功能，但断言必须指出对应行为。

## 前端共同验收矩阵

所有影响界面的迁移项，除各自 TC 外，统一叠加以下检查：

1. 两个真实实例同时存在；修改 A、运行 A 或销毁 A 不污染 B。
2. 画布与 Graph 往返；Active/Mute/Bypass 往返；恢复正确面板、内容和媒体状态。
3. 保存工作流、刷新页面、重开工作流；结构、值、槽位、素材引用及布局保持，临时焦点与忙碌状态不被错误保存。
4. 50%、100%、150% 画布缩放；1920×1080、1280×720、680×720 视口；菜单在边缘仍可操作，标题/Slot/连线锚点一致。
5. Tab、Enter、Escape、Delete/Backspace、Ctrl+Z/Y/Shift+Z 及中文组合输入。编辑文字时保留文字快捷键，不误触画布删除。
6. 悬停、焦点、选中、禁用、忙碌、错误、空态、长内容；无溢出、重复滚动、被遮挡焦点或不可访问图标。
7. 隐藏、切换和销毁后释放事件、Observer、定时器、媒体和 object URL；不得由面板关闭取消后台真实任务。

涉及提供方时，前端矩阵首先用假服务完成；真实生成仅使用本地 Qwen/MiniMax 验证对应边界，不代替界面回归。

## 后端故障矩阵

| 注入位置 | 预期状态与动作 | 禁止行为 |
| --- | --- | --- |
| 校验失败或明确未送达 | 显示具体原因；经明确操作可以重新提交 | 写成成功或保留假 running |
| 提交已送达但应答丢失 | 有幂等/查询能力则核对原任务，否则标 unknown | 自动以新 ID 再发付费请求 |
| 拿到远端 ID 后断网 | 保存 ID，重连后查询同一任务 | 刷新页面触发 create |
| 远端完成但下载中断 | 保持原结果身份，恢复下载并校验文件 | 重跑生成，或把半文件当完成 |
| 写账本或资产目录失败 | 返回明确失败并保持一致状态；重启可核对 | UI 显示已保存但数据丢失 |
| 进程重启时存在任务 | 区分可恢复查询、本地执行丢失和结果未知 | 无依据地将 running 恢复为新执行 |
| 重复、乱序或旧版本结果 | 按 requestId/版本归并；旧结果不覆盖新编辑 | 修改错误行、倒退终态或新增重复素材 |
| 排队取消与远端取消 | 排队项停止派发；远端按能力报告实际结果 | 把本地隐藏当远端取消成功 |

为每个故障至少设置一次确定性注入点，断言持久记录、服务调用次数、UI 投影与结果文件。不能仅断言异常被 catch。

## 性能初版预算

以下是目标预算，尚非实测结果。M0 在固定参考机上核定一次并保存基线；后续变更预算必须记录产品影响和理由，不能为使失败用例转绿而静默放宽。参考机至少 16GB RAM、SSD、1920×1080、DPR=1；实际 CPU/GPU/浏览器版本写入报告，不能用“普通电脑”替代。

测量前完成资源加载并预热 10 秒；每个场景运行 30 秒、重复 5 次，保存每次 p50/p95，不只挑最好一次。输入响应采用输入事件到下一次可见更新；帧时间取连续拖动/缩放期间；加载区分冷/热缓存。

| 编号 | 场景 | 初版门槛 |
| --- | --- | --- |
| PERF-01 | FX-PERF-S 拖动/缩放 | 帧间隔 p95 ≤ 20ms；无超过 200ms 的交互长停顿 |
| PERF-02 | FX-PERF-M 拖动/缩放与表格编辑 | 帧间隔 p95 ≤ 33.3ms；输入到显示 p95 ≤ 100ms |
| PERF-03 | FX-PERF-M 保存/加载 | 序列化保存 p95 ≤ 2s；已缓存媒体下重开至可编辑 p95 ≤ 5s；不等所有视频解码才可编辑 |
| PERF-04 | FX-PERF-L 浏览/取消操作 | 主要操作 p95 ≤ 200ms；可见“处理中”且能取消；操作不导致浏览器无响应 |
| PERF-05 | 反复进入/退出及创建/销毁 20 轮 | 所有已关闭实例订阅/计时器计数回到基线；受控 GC 后最后 5 轮堆中位数不高于前 5 轮 15% 且增长 ≤ 20MiB |
| PERF-06 | 100 个假任务混合执行，含转码 | 健康查询 p95 ≤ 200ms；本地/云/转码并发均不超过配置；无饥饿的待运行任务 |
| PERF-07 | 1 小时标准场景循环 | 无持续增长的活跃资源计数；无丢失编辑、重复提交或无法恢复的任务投影 |
| PERF-08 | 资产库 2000 条收藏的固定搜索序列 | 输入到结果显示 p95 ≤ 200ms；不为搜索同时解码全部媒体 |

无视频场景与视频场景分别报告；浏览器 JS 堆、解码/GPU 占用和后端 RSS 分开记录。GPU 模型速度受硬件与模型影响，不把生成耗时写成通用画布性能门槛。

## 本地 Qwen 与 MiniMax 真实生成验收

只验收这两类模型当前实际支持的本地路径。记录权重标识、节点/执行器版本、GPU、输入模式、限制与真实结果；模型名称相同但调用云端的路径不符合本范围。Qwen 覆盖纳入的本地图像生成及本地提示词优化能力；MiniMax H3 覆盖文生视频、首帧视频与首尾帧视频。表内与表外入口使用同一模型白名单。不支持的模式在提交前拒绝，不能用另一模型成功代替。

| 本地能力 | 当前源码中的精确标识 | 验收边界 |
| --- | --- | --- |
| Qwen 文本优化及图片反推 | `qwen3.5:9b-q4_K_M` | 本地 Qwen 服务路径；不转发 Comfy/DeepSeek |
| Qwen 图片生成 | `Qwen-Image-2.1 Turbo（本地）` | 当前文生图能力；不新增图片参考模式要求 |
| MiniMax 视频生成 | `MiniMax H3 FL（本地）` | 文生、首帧、首尾帧；明确排除云端型号 `Minimax H3` |

这些是源码标识，不代表本轮已检查权重安装或执行成功。目录校验器要求所有 provider-live 用例声明此白名单内的 `live_models`，并使用“仅本地 Qwen/MiniMax”执行策略。

普通 CI 使用假服务；本地真实生成在明确的资源窗口运行，避免影响用户正在执行的任务。缺模型、权重、节点或显存时标为阻塞，保留失败证据，不安装未指定替代模型，不向云端转发。测试配置同时限制执行路径和模型标识，并断言云端提交次数为零。

Comfy 积分、DeepSeek 及其他非白名单通道仍可保留适配代码，测试仅使用确定性假服务验证参数、事件、恢复、错误和费用字段的处理。模拟费用不是实际计费，模拟结果不是模型效果；这些通道的真实输出、质量、水印或费用均标为未验收。它们不作为本轮迁移的真实生成门槛；本地 Qwen/MiniMax 的纳入模式未通过时，对应真实生成范围不能标完成。

## 阶段门禁和证据

每阶段入口、范围和顺序见 [迁移蓝图](BLUEPRINT.md)。当前阶段必须通过 `TC.phase` 不晚于本阶段且适用的 P0/P1；后续阶段才具备前提的 TC 不阻塞较早骨架阶段，但相关功能只能标为阶段性通过。已通过用例在受本阶段改动影响时回归；M6 必须汇总所有适用 P0/P1 的最终候选版本证据。P2 未通过需记录影响和后续安排。所有涉及的宿主矩阵必须有实际证据，不能仅凭自动测试数量交付。

M6 必须包含：仅新包安装、旧包冲突、未知节点保留、素材与收藏迁移、账本兼容、重复迁移、迁移中断、版本升级、离线回滚数据保护，以及完整主流程。这里的离线回滚指无需远端重新生成即可恢复本地备份，不增加独立的离线产品功能范围。

每次执行记录至少包含：TC ID、构建/版本、环境、夹具哈希、步骤偏差、实际结果、通过/失败/阻塞/不适用、截图或日志位置、缺陷 ID、执行日期。只有具备明确适用性理由时才允许不适用；无环境、无预算和未实现属于阻塞或未执行。

| 状态 | 可作出的结论 |
| --- | --- |
| 规格已定义 | 有步骤与期望，尚无执行结论 |
| 自动化已实现 | 测试代码可运行，尚不代表已通过 |
| 自动检查通过 | 对应环境中的自动断言通过 |
| 宿主验收通过 | 真实 ComfyUI 的相关交互和持久化通过 |
| 本地模型验收通过 | 白名单内指定本地 Qwen/MiniMax 路径与模式真实运行通过；不推及其他提供方 |
| 已发布 | 阶段门禁、迁移与版本检查齐全并完成发布 |

现有测试文件应优先复用其语义与夹具，修正路径和服务边界。只断言 CSS 字符串、内部函数写法或本机未跟踪文件的测试不能作为新产品的唯一验收证据。
