# 创作画布单仓库迁移蓝图

日期：2026-10-24。目标是将两个旧仓库中属于创作画布的能力整合为一个产品仓库、一个安装包和一个发布版本，继续依托 ComfyUI。本蓝图定义目标架构与实施门槛；实现与验收状态见新仓库阶段报告，不以本蓝图判断完成。

## 产品边界与完成条件

产品主流程为：导入素材和分镜 → 组织素材和表格 → 编辑及优化提示词 → 表内或表外生成 → 回填及复用结果 → 剪辑导出 → 保存重开及恢复原任务。

“完整”指功能对照表中所有标为保留或重构的能力，以及其支持矩阵内的正常、异常、恢复和兼容场景。徽章、展厅和其他未进入创作流程的历史节点不自动进入新产品。外部 ComfyTV 保持可选、只读上游；新包不捆绑其源码，也不以安装它作为基础创作能力的前提。

产品完成必须同时满足：仅安装新包即可完成主流程；没有指向两个旧仓库的运行依赖；旧创作工作流及所需数据能迁移；本地 Qwen 与本地 MiniMax 的纳入模式完成真实生成验收；阶段门槛有证据。代码存在、测试定义完整和产品验收通过是三个独立状态。

按用户明确要求，真实生成测试只使用本地 Qwen 和本地 MiniMax（现有视频路径为 MiniMax H3），包含提示词优化涉及的真实模型调用。其他模型、Comfy 积分及远端服务只做协议模拟、静态校验和历史数据兼容测试，不安排真实调用，也不得在本地能力缺失时自动替换为云端。本次限制收紧测试范围，不删除产品已有的提供方适配能力；这些通道标为协议测试通过或真实运行未验收，其真实调用不作为本轮迁移退出门槛。

当前范围基线为 Canvas `3176b5a67dbcd0b66f795976e5a81bcdfe346093` 与业务库 `7ff56cb51ef6f7fc3bcf5707792d655037c61b30`。来源、功能决策与案例编号见 [功能对照表](FEATURE_MATRIX.md) 和 [节点注册清单](NODE_INVENTORY.md)。这里的提交号表示本地核对基线，不代表未来宿主支持范围。

## 迁移决策规则

| 决策 | 含义 | 实施要求 |
| --- | --- | --- |
| 保留 | 保留产品行为及可复用的成熟实现 | 可以调整导入与组装位置；保留兼容合同，迁入相关回归样例 |
| 重构 | 保留产品能力，重新组织状态、接口或实现 | 先固定输入输出与行为样例，再替换；用户可见差异单独登记 |
| 不迁入 | 不属于新产品，或已退役且不应恢复执行 | 不注册、不打包；受影响的旧工作流保留原始数据并报告缺失能力 |
| 暂缓 | 有潜在价值，但不属于首版完成条件 | 不在菜单暴露半成品，不以预留目录冒充已支持 |

同一能力中的实现重构不构成修改既有行为的授权。源码与已批准交互规范不一致时，登记差异，在 M0 或该能力进入阶段前通过真实宿主核对后确定基线；不能静默选择较方便的一方。

清单按四个视角组织：F-CAN 是画布能力，F-BIZ 是业务能力，F-SYS 是跨模块工程要求，F-OUT 是排除明细。它们是可追踪的决策条目，不是互不重叠的独立功能计数。F-BIZ-039/040 汇总历史排除范围，具体取舍以 F-OUT 明细为准。拆实施任务时同一实现只有一个负责模块，其他编号作为关联要求，不能据此重复建设或重复排期。

## 模块与依赖方向

| 所有者 | 可以依赖 | 禁止承担的责任 |
| --- | --- | --- |
| design 与 ui | 语义 token、纯类型、组件参数 | 读取图、识别模型、提交任务、复制业务状态 |
| contracts 与纯领域规则 | 标准库及明确的校验依赖 | DOM、宿主全局对象、网络、文件系统 |
| canvas 与 features | contracts、ui、注入的服务端口 | 跨功能访问私有 DOM、私有面板属性或直接导入提供方 |
| application | 功能公开接口、端口、组装配置 | 为每个功能再写一套业务规则 |
| backend 业务服务 | contracts、jobs、assets、提供方接口 | 依赖浏览器是否挂载来维持任务 |
| integrations 与 providers | 外部 API、内部端口 | 把兼容分支扩散到每个组件 |
| compat | 版本化旧格式及转换接口 | 成为永久的第二套可写模型或执行引擎 |

新增前端核心与接口采用 TypeScript 或等价的严格类型检查；成熟纯 ESM 逻辑可直接迁入并逐步类型化。首轮保留已经复用的 DOM 控件，组件陈列与产品同源。框架迁移只有在能减少维护成本且通过宿主接入验证时再单独决策，不要求为建新仓库把所有控件重写成 Vue。

Python 服务先保持单体模块化，通过 ComfyUI 的服务和队列接入。无需起步引入 Redis、独立调度集群或自研执行引擎。CPU 密集的解析/转码和阻塞文件操作离开事件循环，按实际任务采用线程或受控子进程，并定义取消与清理出口。

跨层非法导入、循环依赖、硬编码旧仓库资源路径和无所有者的共享模块进入静态检查。跨功能动作由 application 组装，所有输入输出经过公开接口。不得用无类型全局事件总线隐藏依赖。

## 数据权威与编辑事务

| 数据 | 唯一权威 | 保存与恢复 |
| --- | --- | --- |
| 节点、连接、参数与卡片布局 | ComfyUI 工作流，经宿主适配器修改 | 保留原生图及 `daelabCreativeCanvasV1`；不创建平行可写图 |
| 表格、提示词和剪辑内容 | 对应文档控制器的编辑命令 | 同一事务写回既有工作流字段；重载以工作流恢复，视图仅是投影 |
| 撤销与重做 | 宿主历史边界，经统一桥接 | 一次用户编辑一个事务；派生同步并入原事务；视口移动不清空重做 |
| 任务身份、状态、快照与结果 | 后端任务账本 | 浏览器仅保存显示缓存及引用；恢复核对原任务，不重复提交 |
| 资产、来源、收藏与文件引用 | 后端资产目录 | 迁入浏览器旧收藏；URL 是访问地址，不充当资产身份 |
| 焦点、悬停、选择、播放位置 | 视图会话 | 临时状态，面板卸载后释放；需要临时恢复时按工作流会话隔离 |
| 凭据 | 后端连接管理 | 不进入工作流、日志正文、测试样例或前端状态快照 |

文档控制器是编辑入口，不能与工作流各自独立接受写入再相互覆盖。所有编辑带稳定 document/record/field 身份；异步请求另带 workflow session、epoch、requestId、输入版本。撤销只恢复编辑数据，不倒退执行事实；过期结果保留为可查看结果，不能自动覆盖新内容。

剪辑与表格的派生联动由应用层发起，统一历史桥接负责事务，不包含剪辑或表格的具体规则。无法完全消除的 ComfyUI 内部 API 访问集中在 integrations/comfyui，记录使用点、失效检测与版本回归用例。

## 任务与资源管理

新任务领域统一为 jobs；提供方和功能不各建独立任务账本。建议本地单用户部署使用版本化 SQLite 账本，媒体文件仍独立存储。先适配旧回执，再迁移到统一模型；保留 requestId、输入指纹、原提供方任务 ID、来源与状态含义。

状态至少区分待提交、提交中、已提交、执行中、取回结果、成功、失败、等待恢复、提交结果未知、已取消。操作区分三种语义：暂停后续派发只停止尚未提交的排队项；本地执行中断必须确认原任务已停止，继续时明确创建新的原生执行记录并重跑当前行；已提交云任务继续跟踪原身份，远端取消仅在提供方支持时提供。不同提供方未必支持查询、幂等键或取消，能力探测决定可提供的操作。

在外部服务不提供幂等或查询的情况下，不承诺跨网络的绝对恰好一次。提交成功但应答丢失时标为结果未知，禁止自动重新提交；可核对原任务时恢复查询或下载。用户明确发起新的生成必须生成新的任务身份，并显示旧任务状态。

本地 GPU、云请求和媒体转码分别设置资源额度与排队策略。默认额度由参考机和提供方限额配置，不能照搬旧实现的并发数字。后端检查请求大小、文件范围、输入快照、能力限制和资源额度；一个提供方缺少依赖不能导致基础画布导入失败。

本地任务的“继续重跑”与云任务的“恢复查询”使用不同操作和提示；逻辑任务保留原关联，新的本地 attempt/prompt ID 单独记录。仅中断本产品可确认拥有的执行，不用宿主全局中断误伤其他工作流。

任务日志至少可以按 requestId、节点/记录 ID、provider task ID 关联，不记录凭据。公开错误包含可读原因、是否可重试、可恢复的原任务身份。健康检查区分核心服务可用、提供方不可用和资源不足。

## 组件和交互规范

现有共享按钮、字段、主题、字体、图标、Slot、面板活动状态与实例释放合同作为首版基线。所有组件登记唯一源码入口、参数/事件、变体、消费方、可访问名称及销毁行为。共享实现不共享实例业务状态。

每种交互按“触发条件 → 状态变化 → 提交/取消 → 历史 → 持久化 → 错误”描述。必填检查包括中文输入法、键盘、焦点、长内容、屏幕像素与画布坐标、缩放、边缘菜单、Active/Mute/Bypass 和两个实例隔离。Graph 与创作画布往返应恢复宿主面板；不重建徽章/展厅旧 App Mode。

设计 token 与控件实现是唯一维护入口；规范描述行为，案例记录验收。辅助陈列使用正式控件，不以 gallery build 或 CSS 断言代替真实 ComfyUI 验收。新建节点、素材填充、连线和表格编辑各自声明历史事务，不能通过直接 DOM 改写绕过文档控制器。

## 实施顺序与阶段门槛

| 阶段 | 交付范围 | 验收与退出标准 |
| --- | --- | --- |
| M0 范围和基线 | 功能/节点清单、真实工作流样本、行为差异、版本和性能基线、数据备份约定 | 每个导出节点有归属；保留/重构能力有用例和测试；差异有处理人及关闭条件；参考机和宿主版本固定 |
| M1 产品骨架 | 单包注册、构建发布、模块依赖、共享组件、宿主桥接、错误及配置骨架 | 干净 ComfyUI 仅装新包可启动；本阶段注册无重复；测试专用最小面板通过两实例、模式往返和保存重载；禁止旧目录依赖；测试夹具不进入正式发布包 |
| M2 素材与画布 | 文本、上传、导航选择、组、Slot/连接、剪贴板、历史、资产目录 | 素材导入→组织→连接→保存重开跑通；旧素材/收藏迁入；失败不破坏原素材；对应 P0/P1 与性能预算通过 |
| M3 表格分镜和提示词 | 表格编辑、素材填充、DOCX 导入、引用、配置模板、提示词修改与优化流程 | 文档→表格→提示词可完整编辑；输入类型、行列稳定身份、中文输入、undo/redo 和异步冲突通过；本阶段可使用模拟优化服务 |
| M4 生成与恢复 | 表内/表外生成共用服务、账本、提供方、资源额度、进度、结果回填 | 模拟服务故障矩阵通过；刷新/重启恢复原身份；仅本地 Qwen/MiniMax 纳入模式完成真实验收；其他通道只做协议模拟，不列真实生成门槛 |
| M5 剪辑与完整流程 | 多组时间轴、编辑与预览、导出、完整创作场景、性能治理 | 导出媒体属性与编辑设置一致；跨功能完整流程通过；长时运行和资源释放达标；所有纳入能力具备验收证据 |
| M6 迁移和发布 | 预检、备份、旧数据转换、安装切换、回滚、诊断、用户指南 | 无两个旧库运行依赖；兼容样本、断点恢复、回滚演练通过；清洁机器安装验证；版本/资源一致；遗留问题显式登记 |

M1 中就建立契约、任务和资产端口，但只实现支撑当前端到端流程的最小骨架。功能的 phase 表示主体交付阶段；测试的 phase 表示最迟具备执行条件的阶段，跨阶段能力按测试逐级验收。M4 的故障测试及 M6 的迁移工具可提前开发；M6 汇总全部适用的 P0/P1。不要先把所有旧前端移完，再集中处理后端和保存兼容。

最小首条流程为：单包启动 → 上传图片与输入文本 → 编组与连线 → 撤销重做 → 保存重开。第二条为：分镜导入 → 表格编辑 → 模拟生成 → 回填结果 → 输出素材组。第三条仅接本地 Qwen/MiniMax 的真实生成和剪辑。这样每阶段都有可运行产品行为。

## 迁移与回滚

1. 预检当前宿主版本、两库版本、工作流所用节点、input/output 引用、收藏目录和任务记录。生成只读清单，未知节点和缺失素材必须逐项报告。
2. 等待在途任务结束，或记录其远端身份及可恢复方式。不能把内存 worker 视为已经迁移；不可恢复的在途任务阻止切换。
3. 备份工作流、任务账本/回执、资产目录、配置与迁移清单；保护凭据。保持媒体原路径可解析，确需移动时建立明确映射并核验文件。
4. 停止旧环境，在隔离数据副本上执行版本化、可重复的迁移。中断后可继续或恢复备份，不覆盖原始工作流。
5. 停用两个旧包后启用新包。新包检测冲突并报告路径，不依赖加载顺序覆盖注册。不得自动删除旧目录。
6. 验收导入、编辑、保存、重载、任务恢复和素材引用；再次迁移不新增重复资产/任务/收藏。未迁节点保持原始数据并报告，不能静默删除。
7. 回滚恢复旧代码基线与迁移前数据副本。新版本产生且旧版不理解的数据单独导出保全；只回退 Git 不算数据回滚。

兼容层的每个旧路由/格式必须有来源版本、消费方和删除条件。已退役 LibTV 服务仅允许读取历史记录和结果，不借兼容路由重新启用提交。新运行内部使用 generation/providers/jobs 命名；旧路径只在 compat 内出现。

## 项目管理与发布规则

新库开始承接功能后，两个旧库仅处理迁移阻断问题；修复进入新库对照记录，避免双向长期开发。M6 通过后，后续需求统一进入新库，旧库保留来源说明与历史版本。

每项开发任务关联 F 功能编号、UC 功能用例、TC 测试用例、目标模块和阶段。完成状态依次为待实施、实施中、自动检查通过、宿主验收通过、已发布；不能用一个“完成”覆盖全部状态。跨模块改动在同一个 PR 中交付接口、消费方、迁移和测试。

PR 完成条件：功能行为明确、接口及数据归属无冲突、相关自动检查通过、真实宿主证据齐全、兼容与性能影响已处理、文档更新到最终状态。真实生成测试只允许本地 Qwen/MiniMax；普通 CI 使用假服务，文档核对不执行生成，云端及付费真实测试不在本方案内。

发布版本统一管理前端、Python、schema 和兼容层；前后端暴露版本与构建指纹用于缓存诊断。README 只描述当前支持的安装方式，历史 PR 和旧安装命令移入历史记录。保留第三方来源、字体图标许可证与原始归属，不把新仓库的建立当成重新许可。
