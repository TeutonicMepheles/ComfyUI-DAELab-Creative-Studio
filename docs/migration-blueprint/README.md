## 首批实施任务

1. 完成 M0：固定真实工作流样本、锁定宿主与参考机基线。表格已确认素材/提示词/生成三列及 3 行，多素材追加与 500 行/64 列边界。
2. 建立 M1：新库骨架、单包组装、共享控件、宿主桥接与依赖检查。
3. 交付第一条完整流程：上传与文本 → 编组与连线 → 撤销重做 → 保存重开。

逐项开发任务必须携带 F/UC/TC 编号；后续每阶段以验收证据推进。真实生成测试仅使用本地 Qwen 和本地 MiniMax，禁止云端及其他模型真实调用；普通 CI 使用假服务。本轮限制不删除提供方适配能力，其他通道保持真实运行未验收。

## 数据维护与校验

权威清单为 `catalog/canvas.json`、`business.json`、`system.json` 和 `exclusions.json`。蓝图、测试策略和节点盘点为人工维护的架构文档。来源前缀 `canvas:` 与 `business:` 指两个固定旧仓库提交；`source-manifest.json` 保存 277 个来源文件的 SHA-256、大小及行数，链接指向固定提交，不依赖旧目录。

在新仓库独立检出中运行（无需旧仓库）：

```sh
node docs/migration-blueprint/render_catalog.mjs --write
node docs/migration-blueprint/render_catalog.mjs --check
```

校验覆盖 ID 唯一性、功能与用例的测试关联、字段和阶段、来源文件/行号、本地模型白名单及生成文件一致性。它只校验方案，不会执行产品用例或启动 ComfyUI。执行追踪工具见 [验收目录说明](../validation/catalog/README.md)。
