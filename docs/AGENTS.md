# Documentation ownership

- Keep one authoritative contract for each behavior and link it from module READMEs.
- Follow [WRITING.md](WRITING.md) for tone, evidence wording and README structure.
- Use short, factual statements. Remove repetition and unsupported claims; keep necessary commands, constraints and evidence limits.
- Distinguish specification, current implementation, executed evidence and unverified requirements.
- Preserve dated failures and historical conclusions; prepend/append current status with provenance instead of rewriting past records.
- Generated catalog views must be regenerated from their JSON owner, not patched independently.
